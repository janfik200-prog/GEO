# MEAS1 — замер шума главной меры S (`openlin_ref_match.curve_score`): объявление до прогона

Записано 11.11.2026, до кода и расчёта. Решение Артура: «давай начнём с
устойчивости меры». Повод — аудит шага 6 ANFU: при сдвиге линий на десятки
метров S падает на ≈ 0,01 у любого направления сдвига (компоненты сливаются,
ранги длины перестраиваются). Шапка `openlin_ref_match.py` сама требует: «порога
различия двух S из замера нет: пока он не измерен (нужен замер разброса S,
например по независимым половинам эталона), сравнение описательное».

## Роль и счётчик
Утсйоки — настройка; замер описательный, p-проверок нет, `MEAS1_N_TESTS` = 0.
Лапландия, резервные листы anfu_test1/2 не трогаются. Мера S и её функции не
меняются (только вызываются на возмущённых входах).

## Наборы и семейство
Три набора «весь лист» (C_all) Утсйоки: снимок UTS1 (`_настройка1`), рельеф
RELU1 (`_рельеф1`), Анфиса LINB2 (`_анфиса2`). K = 103 (L до 1030 км) — по самому
короткому набору (UTS1, 1039 км) на НЕвозмущённых входах; при возмущениях K не
пересчитывается (иначе шум K смешается с шумом S). Сдвиги нуля — общие
(`rm.shifts`, 159, зерно 11), как в мере.

## Возмущения (каждое не должно менять качество набора)
1. **П1 — перенос всего набора** на 1 пиксель (20 м) в 8 направлениях. Ранги
   длины не меняются, меняется только совпадение ячеек. 20 м — шаг сетки, в 15
   раз меньше допуска 300 м.
2. **П2 — дрожание линий**: каждая линия набора переносится параллельно себе на
   d по нормали к её главной оси (PCA пикселей линии), знак случайный на
   линию; d = **20 м и 40 м** (1 и 2 пикселя; меньше и чуть больше пикселя
   GLO-30 30 м — точность положения входов). **20 зёрен** на d: относительная
   ошибка оценки SD ≈ 1/√(2·19) = 0,16. Линии — из файлов линий наборов
   (UTS1/RELU1: `C_all_pts`/`C_all_id` в `_линии.npz`; LINB2: метки `ids` в
   `_анфиса2.npz`). Пиксели вне листа/вне общих ячеек отбрасываются. Это и есть
   найденный аудитом механизм (слияние компонент); П2 мерит, насколько он
   шевелит S.
3. **П3 — половины эталона**: линии GTK (по номеру линии `fid`) случайно
   делятся пополам, **20 зёрен**; S каждого набора считается отдельно по каждой
   половине (нуль — те же сдвиги, только ячейки этой половины). Мерит шум от
   того, какие именно линии эталона есть на листе.

## Что печатается
Для каждого набора: S исходное; среднее и SD S по П1, П2(20), П2(40), П3.
Для пар (LINB2 − RELU1, RELU1 − UTS1, LINB2 − UTS1): ΔS исходное; среднее и SD
ΔS при одном и том же возмущении обоих наборов (П1 — то же направление; П2 — то
же зерно, знаки разыгрываются отдельно на каждый набор; П3 — та же половина).

## Правило на будущее (объявляется сейчас, до результатов)
**Порог различия двух S** на листе = 2 × наибольшее из SD ΔS пары по П2(40) и
П3 (берётся наибольшее по трём парам). Различие меньше порога — «в пределах
шума меры», без слов «лучше/хуже». П1 и П2(20) — для сведения (П2(40) строже).
Порог действует для будущих сравнений на Утсйоки; для другого листа — свой
замер тем же кодом. Пересмотр LINB2 против RELU1 этим порогом — описательный
(LINB2 уже имеет вес «согласуется с разбором»).

## Что дальше (не в MEAS1)
Если шум велик относительно различий наборов — отдельным объявлением мера
устойчивее (например, ранжирование и направление по линиям, а не по
8-связным компонентам). Выбор её — по шуму (те же П1–П3), а не по тому, какой
набор выигрывает.

## Агенты
`openlin-registrar` — это объявление; `openlin-auditor` — после прогона.

## Поправка 1 (11.11.2026, по проверке `openlin-registrar`, до прогона)
0. **Замер не слепой.** До объявления видены: плацебо шага 6 ANFU (ΔS среднее
   −0,016, SD 0,0041), оценка аудита «шум ≈ 0,01» и перевес LINB2 − RELU1 = 0,023.
   Поэтому правило ниже выводится из арифметики, а не из «≈ 2×».
1. **Порог пары — вместо «2 × наибольшее SD»:** для каждой пары
   `порог = 1,96 × √(SD_П2² + SD_П3²)`. 1,96 — двусторонние 95 % нормального
   закона для разности; два источника шума (геометрия набора и выборка
   эталона) независимы и складываются дисперсиями. Берётся порог своей пары, а
   не наибольший по парам. **Это не доверительный интервал различия методов**,
   а уровень, ниже которого различие нельзя отличить от шума самой меры:
   формулировка — «в пределах шума меры».
2. **П2 — смещение отдельно.** Сдвиг систематически роняет S (слияния компонент,
   зависит от густоты набора). Среднее ΔS пары при П2 печатается отдельной
   строкой («смещение П2») и в порог не входит; если |смещение| > SD_П2, это
   пишется в итог как ограничение меры.
   **Растеризация П2:** сдвиг постоянен на всю линию и округляется до целого
   пикселя один раз, поэтому разрывов внутри линии нет; компоненты, направления
   и ранги мера пересчитывает сама, как всегда (8-связность). Линии, сходящиеся
   в узле одной компоненты, двигаются независимо (у каждой свой знак) и могут
   разойтись — это часть замеряемого шума.
3. **d для порога — 60 м**, а не 40: медиана |сдвига| шага 6 ANFU (60 м) —
   единственный замер геометрического шевеления линий на этом листе. 20 и 40 м
   печатаются для сведения (кривая «шум от d»). Порог строится по П2(60).
4. **П3 точно.** На каждом из 20 разбиений эталона по номерам линий: ΔS пары по
   половине А и по половине Б; величина разбиения — (ΔS_А − ΔS_Б)/2; SD_П3 — SD
   этой величины по 20 разбиениям (оценка шума для ПОЛНОГО эталона по правилу
   «половина против половины»; пул из 40 значений не используется). Для
   набора — то же по S. Нуль половины: те же 159 сдвигов, ячейки эталона на
   каждом положении отбираются по `fid` из того же `rm.positions`. Ограничение:
   линии эталона разной длины и соседние линии одной зоны не независимы —
   SD_П3 может быть занижен.
5. **Контроль входа.** Метки линий UTS1/RELU1 (из `C_all_pts/C_all_id`) в общих
   ячейках совпадают с масками C_all (проверено до объявления: 51 953 и 142 878
   ячеек, совпадение 100 %; лишние точки файла лежат вне общих ячеек); у LINB2
   метки `ids` — 1904 линии. Прогон печатает это и S невозмущённых наборов,
   которые должны совпасть с 0,071 / 0,110 / 0,133 (LINB2_RESULTS) до 0,001;
   иначе остановка.
6. **K = 103 фиксирован.** Длина каждого возмущённого набора печатается; если
   UTS1 после возмущения короче 1030 км, это помечается (хвост кривой
   сплющивается — смещение, не шум), значение всё равно входит.
7. **Зёрна.** П3: разбиение общее для всех наборов. П2: знаки независимы для
   каждого набора (зерно 1000·(k+1) + номер набора). П1 — 8 направлений, SD с
   ошибкой ≈ 27 %, диагональ = 28 м; только для сведения.
8. **Где порог применим:** Утсйоки, семейство «весь лист», K = 103, эти три
   пары. Для нового набора или другого K — тот же код с этим набором (новый
   замер), а не перенос числа.

## Поправка 2 (11.11.2026, по перепроверке `openlin-registrar`, до прогона)

   возмущённые (у RELU1 81 ячейка маски вне общих ячеек; у UTS1 и LINB2 нет).

   линий LINB1, не подряд); остановки по нему нет.

## Поправка 3 (11.11.2026, после остановки на контроле входа; S возмущений не считался)
Прогон по поправке 2 остановился на контроле: RELU1 с обрезкой по общим ячейкам
(−81 ячейка, ≈ 2 км) дал S 0,1080 против опубликованных 0,110 (UTS1 0,0710 —
совпал). Поправка 2 п. 1 отменяется: наборы НЕ обрезаются по общим ячейкам ни в
исходном, ни в возмущённых вариантах (как в опубликованных S; ячейки эталона и
так берутся только в общих ячейках). Возмущённые пиксели отбрасываются только
за краем растра. Контроль 0,001 и остальное — без изменений.
Наблюдение (описательно, само по себе данные о шуме): удаление 0,07 % ячеек
набора на краю листа сдвинуло S на 0,002.
