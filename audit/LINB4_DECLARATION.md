# LINB4 — отбор линий Анфисы по геометрии (расстояние между концами): объявление до прогона

Записано 13.11.2026, до кода. Решение Артура: «давай сделаем оба шага» (после LINB3:
на Каррисо, Лост-Ривер, Дикси случайный отбор той же длины ближе к опубликованным
разломам, чем отбор по P — упорядочивание по вероятности хуже случайного).

## Правило (одно)
LINB4 = LINB2 (линии LINB1, растр, бюджет = длина набора «рельеф», мостики при растре), **но
порядок — по убыванию расстояния между концами ломаной** (хорда, м; длинная и прямая линия —
большая хорда), ничьи — по длине пути, затем по номеру. P в отборе не участвует. Нового
числа нет.

## Где и как читается (описательно, `LINB4_N_TESTS` = 0) — как LINB3 с поправкой 1
1. Утсйоки: S, ΔS(LINB4 − LINB2) против 1,96·√2·SD_П3 пары (20 разбиений, зёрна 5000+k).
2. Участки TS2 (GEM/GIF): выше k из 19 при 100/300 м; разница с LINB2 читается, если
   |Δk| > ширины IQR случайного отбора той же длины на этом участке (100 раз, зёрна 10000+s).
3. Доля длины LINB4 в линиях ≥ 3 км и медиана длины линии — против LINB2 (описание).
**Утечка**: правило придумано, глядя на всю таблицу TS2/LINB3 (Каррисо, Лост-Ривер, Дикси) —
участки TS2 читаются только как «не сломалось/сдвинулось»; независимая проверка — Лапландия,
отдельным объявлением со своим слагаемым (prior 160). Решения «принять» нет — Артур.

## Агенты
`openlin-registrar` — объявление; `openlin-auditor` — после прогона.

## Поправка 1 (по проверке openlin-registrar, 13.11.2026, до прогона)
`git fetch`: новых коммитов в origin/lineaments нет. Кода LINB4 ещё нет. Замечания:

1. **Хорда в метрах.** Линии лежат в единицах сетки 100 м (`length_m` = путь × `CELL_M`).
   Хорда считается так же: `hypot(*(pl[-1] − pl[0])) · CELL_M`; ничья по хорде — по
   `length_m`, затем по номеру (как в `linb2_pick`, `np.lexsort`). Сравнение ведётся только
   внутри одного набора линий, масштаб на порядок не влияет, но единицы обязаны совпасть с
   `length_m`. Замкнутые ломаные (концы рядом) получают хорду ≈ 0 — это следствие правила,
   печатается их число и доля длины.
2. **Тавтология длины.** Разломы GEM/GIF и эталон GTK — длинные и крупные; порядок по хорде
   выбирает самые длинные линии при том же бюджете, то есть выигрывает по построению
   независимо от прямизны. Случайный отбор той же длины (п. 2) этого не снимает: он случаен
   и по длине. Поэтому к трём прогонам добавляется контроль (описательно, N_TESTS = 0):
   **LINB4L — тот же бюджет, порядок по длине пути `length_m` по убыванию, без хорды и P**
   (ничьи — по номеру). Прямизна читается как вклад только там, где LINB4 лучше LINB4L
   больше ширины IQR случайного отбора на участке (п. 2) и больше 1,96·√2·SD_П3 на Утсйоки
   (п. 1). Если LINB4 ≈ LINB4L — выигрыш объясняется длиной, не геометрией, и так и пишется.
   Дополнительно: случайный отбор тоже печатается среди линий не короче медианы длины набора
   (медиана — измерение на самом наборе, не круглое число).
3. **Утечка.** Верно, что правило придумано по всей таблице TS2/LINB3; п. 2 читается как
   «не сломалось/сдвинулось». Добавка: GTK на Утсйоки тоже только крупные линии (память
   `gtk-is-not-full-target`), так что рост S при отборе длинных линий не доказывает, что
   найдены «все линеаменты» — цель ветки; пишется в отчёте.
4. **«≥ 3 км» в п. 3** — число без источника. Заменяется: доля длины в линиях не короче
   медианы длины LINB2 того же листа (измерение), порог 3 км не использовать.
5. **Счётчик.** `LINB4_N_TESTS` = 0 верно (p-значений и решения нет). Для Лапландии —
   новое слагаемое, prior = последнее звено цепочки (RELU4, 160) + его тесты, α = 0,05 / сумма,
   n сдвигов ≥ 2/α − 1, запас α·(n+1) ≥ 2 — в отдельном объявлении.
