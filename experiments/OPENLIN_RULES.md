# Ветка линеаментов (`experiments/openlin_*`): правила и состояние

Короткая база знаний для агентов и новых сессий. Читать целиком перед любой
работой в ветке. Состояние на 28.09.2026.

## Цель и границы

- Цель — **линеаменты по космоснимку**, а не разломы. Совпадение с картой
  разломов — сверка после построения, не критерий отбора.
- Ветка **отдельна** от прогноза золота (`src/`, модель, критериальный метод).
  Работу из `openlin_*` в конвейер прогноза не переносить.
- **Рельеф, гравика, магнитка и геологическая карта во вход не идут** —
  только для сверки после. Смысл метода: геолог размечает линеаменты по
  снимку, значит и метод обязан работать по снимку.
- Эталона нет. Когда появится — только сверка и оценка полноты, не обучение.

## Текущий метод

Модуль: `experiments/openlin_zone_lines_v3.py` (имя историческое, внутри —
рабочая конфигурация). Запуск из корня:

```bash
python -m experiments.openlin_zone_lines_v3 --site anabar            # красный канал
python -m experiments.openlin_zone_lines_v3 --site anabar --канал ndvi
```

Вход — зимний композит Sentinel-2, 12 сцен при солнце 7.7–9.6°, 20 м
(`datacache/s2_lowsun/composite/winter_anabar_20m_лист.npz`). Тракт: поиск
теней (гребень, нормировка по окрестности 2 км, утончение, гистерезис
97/90 %) → продолжение концов (отрезок 200 м, предел 900 м) → сшивка (пять
условий) → отсев швов → подтверждение двумя половинами (сцены внутри плитки
через одну; ≥ 30 % длины в 60 м от линий КАЖДОЙ половины). Карта зон
согласия («Кора» на признаках согласия приборов, 100 м) — признак линии, не
фильтр. Итоги: `outputs/metrics/openlin_zone_lines_anabar_v3[_ndvi].npz`,
логи `outputs/metrics/_zone_lines_*.log`, окна для глаза —
`outputs/линеаменты_проверка[_ndvi]/`.

Последний закреплённый результат (красный канал): в зонах 179 линий / 326 км,
все четыре условия пройдены; весь лист 1729 / 2605 км, не пройдена длина.
NDVI: 180 / 326 км, пройдены все четыре, но мусор 15.4 % против 6.2 % у
красного; 57–62 % линий повторяют красный, новые — в основном контуры пятен.

## Дисциплина (нарушение = прогон не засчитывается)

1. **Числа только из замеров** или арифметики порога: процентиль измеренной
   величины, квантиль нуля, n ≥ 2/α − 1. «Круглые» числа запрещены.
2. **Объявление до прогона** — блок комментариев в коде: что проверяется,
   откуда каждое число, условия приёмки, добавка к счётчику, число сдвигов.
3. **Условия приёмки** (для каждого набора): мусор этапа подтверждения
   ≤ 20 %; сдвиговый нуль p ≤ 0.05 / N; устойчивость ≥ 0.5 и ≥ 2× нуля;
   медиана длины ≥ 1.5 км. **Пороги не двигаются после прогона**, даже на
   0.7 п.п. «Почти прошло» — не прошло.
4. **Счётчик проверок против набора линий** — цепочка слагаемых, одно на
   прогон (блок «ЦЕПОЧКА СЧЁТЧИКА» в `openlin_zone_lines_v3.py`, восстановлен
   по логам 28.09.2026): `ZL` 18+3 → `EXT` 21+3 → `NMS` 24+3 → `PAR` 27+6 →
   `SHEET` 33+6 → `H200` 39+6 → `SYM` 45+6 → красный канал сейчас 51 → `NDVI`
   51+6 = 57. Новый прогон добавляет СВОЁ слагаемое СВОЕЙ строкой
   (`*_N_TESTS_PRIOR` = прежний prior + прежние свои), старые не трогает.
   Повтор уже проверенной конфигурации слагаемого не добавляет, но идёт против
   всего счётчика на момент повтора. Отдельный счётчик против карты разломов —
   `openlin_invariant.KORA_INV_N_TESTS_PRIOR` = 231.
5. **Достижимость**: при n сдвигах пол p = 1/(n+1); требуется пол ≤ α/2
   (запас ≥ 2×). Красный канал: 4000 сдвигов при 0.05/51 — запас 1.96×, ниже
   нормы, поэтому следующий прогон красного — не меньше 5000. NDVI: 5000 при
   0.05/57 — запас 2.2×.
6. **Мусор — поэтапно**: трассировка → зона и направление → подтверждение;
   ноль на позднем этапе проверять на то, не родился ли он на раннем.
7. **Проваленные конфигурации остаются в коде** комментарием с цифрами.
8. **Глазная проверка обязательна**: парные окна (чистый снимок / разметка)
   и контрольные окна; машинные проверки не видят слипания соседей и швов.

## Известные ловушки

- Патчи через bash heredoc **молча не применялись** — править файлы только
  редактором и после правки grep-ом проверять, что изменение в файле.
- git не признаёт папку (другой владелец): все команды как
  `git -c safe.directory=D:/projects/GEO ...`; глобальный конфиг не трогать.
- `команда | head` убивает долгий прогон; фоновый запуск через `&` умирает
  вместе с оболочкой — запускать без `&`, в фоновом режиме инструмента.
- До 23.09.2026 утончение (`openlin_lines._ridge_nms`) было слепо к
  меридиональным и широтным линиям: все выводы ветки о направлениях до этой
  даты цензурированы, включая карту доклада 16.09 (255 линий, 1010 км).
- Половины неравные: 8 сцен против 4, на 77 % листа половина «Б» — одна
  сцена. Подтверждение упирается в неё.
- Линии у воды (40 %+) — не артефакт: русла под ними вчетверо прямее фона.
- Слепая полоса освещения — ±15° у меридиана (солнце 184°).

## Открытые задачи (по приоритету)

1. Отличить разломы от гнейсовидности (шаг между соседями одного
   простирания, гладкость поля простираний, сверка с контактами — после).
2. Подтверждение по непрерывному отклику или голосованием k из 12 сцен
   вместо двух половин: снимет асимметрию «сшито / не сшито» и 8 против 4.
3. Слепая разметка геологом → точность и полнота в процентах.
4. Условие для полной карты вместо медианы длины — объявить до прогона.
5. Перенос на другую площадку с замороженными порогами.
6. Тесты на инварианты ветки (их пока нет ни одного).
