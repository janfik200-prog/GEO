# Воспроизведение результатов — ИПУЗ-2026, лист R-48-XI,XII

Релиз воспроизводит **точный пересчёт опубликованных метрик и карт** из
производных таблиц. Полный путь от спутниковых сцен до признаков здесь не
воспроизводится: исходные сцены и закрытые слои в пакет не входят (см.
`OPTIONAL_DATA` в `RELEASE_MANIFEST.json`). Эти две вещи не следует путать.

## Что лежит в релизе

| Каталог | Что |
|---|---|
| `01_inputs/` | сетка листа, критериальный балл, валидная маска, обучающая метка |
| `02_protocol/` | восемь полос, их состав, манифест, независимый геометрический аудит |
| `03_runs/` | полный журнал тестов с кодом возврата и версиями |
| `04_metrics/` | замороженные таблицы 27.10.2026 и независимые пересчёты |
| `05_maps/` | три GeoTIFF, три PNG, проверка геометрии, точка входа `make_maps.py` |
| `06_article/` | статья и переносимая сборка `build_article.py` |
| `07_repro_package/` | копия кода, замороженные зависимости, `MANIFEST_SHA256.csv` |
| `docs/` | этот файл, ограничения, реестр утверждений, статусы, задание на продолжение |
| `qa/` | проверка переносимости, аудит релиза, причины пропусков |

## Минимальный прогон в новом каталоге

Команды не требуют прав администратора и не меняют глобальные пакеты Python.

```bash
# 1. Распаковать релиз в произвольный каталог
cd /куда/угодно/ipuz_release

# 2. Отдельное окружение
python -m venv .venv
. .venv/bin/activate              # Windows: .venv\Scripts\activate
pip install -r 07_repro_package/env/requirements_exact.txt

# 3. Тесты проекта
cd 07_repro_package/project && python -m pytest -q -rs ; cd ../..

# 4. Независимая проверка релиза (только чтение)
python 07_repro_package/project/scripts/verify_handoff.py \
       --root . --report qa/verify_handoff.json

# 5. Растры, карты и статья — из любого каталога
python 05_maps/make_maps.py
python 06_article/build_article.py
```

Шаги 3–5 независимы: успех одного не заменяет другой. У тестов и у пересчёта
метрик отдельные отметки PASS/FAIL в `docs/IMPLEMENTATION_STATUS.csv`.

## Что требует данных, которых в пакете нет

`05_maps/make_maps.py` и расчёты рабочей точки читают
`data/processed/operating_point_masked.parquet` и `dataset_v6.parquet` из
рабочего каталога проекта. Если их нет, скрипты останавливаются с перечнем
недостающих файлов и **не подставляют нули или случайные данные**. Путь к
каталогу с данными задаётся ключом `--data-root`.

Полное переобучение (`python -m experiments.operating_point_masked`) требует
всей признаковой сборки и в минимальный прогон не входит.

## Окружение

Опубликованные числа получены на Python 3.13.15 и scikit-learn 1.9.1. Переданный
пакет закреплял Python 3.12.10; прогон тестов на нём не выполнялся, поэтому
утверждение «замороженное окружение прошло целиком» в этом смысле не
заявляется (LIMITATIONS.md п. 14). Рабочая точка при этом совпала с
замороженной побайтово. Версия
библиотеки обучения влияет на результат: при откате на 1.7.2 остаточное O₁₀
смещается с 0,362287 на 0,372763. Поэтому версии зафиксированы в
`07_repro_package/env/requirements_exact.txt` и `env_lock.json`, а не описаны
словами.

Отдельная особенность машины сборки: установщик PostGIS прописывает в систему
`PROJ_LIB` со своей базой PROJ, из-за чего `rasterio` падает на любом
обращении к системе координат. Пакет `src` чинит переменную при импорте
(`src/__init__.py::_fix_proj_data`), отдельных действий не требуется.

## Сверка хешей

`07_repro_package/MANIFEST_SHA256.csv` перечисляет SHA-256 всех файлов пакета
в формате `sha256 *./относительный/путь`. `RELEASE_MANIFEST.json` дополнительно
хранит хеши метрик, растров, карт и статьи.

Одна оговорка: SHA файла `operating_point_masked.parquet` меняется при
перезаписи даже тогда, когда все значения идентичны — различаются служебные
поля формата parquet. Сверять нужно значения (`DataFrame.equals`), а не хеш
файла; хеш фиксируется один раз и файл больше не перезаписывается.
