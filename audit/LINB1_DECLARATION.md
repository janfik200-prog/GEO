# LINB1 — линии из карты Анфисы (вариант Б): объявление до прогона

Записано 11.11.2026, до кода и расчёта. Решение Артура: сначала вариант Б
(линии прямо из карты), если не получится — вариант А (Анфиса оценивает
кандидатов тракта).

## Роль и счётчик
Площадка — Утсйоки, НАСТРОЙКА. Описательно: p-проверок нет, в счётчик ничего
не идёт (`LINB1_N_TESTS` = 0). Слова «значимо» и «доказано» не используются
(правило `openlin_ref_match`: порога различия двух S нет). Лапландия не
трогается (контроль израсходован в FAMLAP).

## Вопрос
Даёт ли набор линий, построенный из карты Анфисы (FAM3, замороженная), большую
главную меру S, чем наборы тракта на том же листе?

## Карта
- Модель: `outputs/fam/frozen_fam3.pkl` (нечёткая аддитивная, 3 зерна,
  заморожена в FAMLAP). Карта P = среднее логитов трёх зёрен, сетка 100 м.
- Нормировка признаков — квантильная по ВСЕМ полным ячейкам листа (не по
  окнам: линии строятся на весь лист). Эталон в нормировке не участвует.

## Построение линий (на сетке 100 м)
1. **Направление и сила.** Для 12 направлений — среднее P вдоль отрезка
   1,1 км (`LINE_LEN_M`, `N_DIR` из FAM: те же ядра, что у признака
   прямолинейности). Сила D = максимум по направлениям, направление θ — где
   максимум.
2. **Порог без эталона.** Ячейка — кандидат, если D > 0. Логит 0 — граница
   решения самой модели: обучение шло со взвешиванием классов, поэтому P > 0
   значит «линия вероятнее фона» при равных априорных. Порог не подбирается.
3. **Тонкая ось.** Подавление немаксимумов поперёк θ: ячейка остаётся, если её
   D не меньше D двух соседей по нормали к θ (±1 ячейка, билинейно).
4. **Сборка.** Скелет оставшихся ячеек (8-связность), разбиение в узлах на
   ветви; ветвь — ломаная по центрам ячеек.
5. **Сшивка.** Концы двух ветвей соединяются, если разрыв ≤ 900 м
   (`V3_GAP_M` тракта), боковой сдвиг ≤ 127 м (`TWIN_OFFSET_M`, одобрен Артуром
   09.10) и разница направлений концов ≤ 20° (`DIR_TOL_DEG`). Жадно, по
   возрастанию разрыва.
6. **Короткие.** Линии короче 200 м (`LINK_MIN_LEN_M` тракта) отбрасываются.
   Других отсевов по длине нет: мера S ранжирует линии по длине сама.
7. **Растр.** Ломаные рисуются на сетке 20 м листа (как маски тракта) —
   `outputs/metrics/openlin_zone_lines_utsjoki_v3_анфиса1.npz`, ключ `C_all`,
   и векторы `..._анфиса1_линии.npz`.

## Мера
`openlin_ref_match` без изменений: главная S (кривая «полнота — длина набора»
против сдвигового нуля, 159 сдвигов, зерно 11, допуск 300 м и 20°, шаг L 10 км,
K по самому короткому набору сравнения). Семейство «весь лист»: снимок (UTS1),
рельеф (RELU1), снимок + рельеф (правило сложения `add_new`), Анфиса, Анфиса +
снимок + рельеф (то же правило). «В зонах» у Анфисы нет — не сравнивается.
Для сведения — `recall_dir` и `long_lines`.

## Что считается «получилось»
S Анфисы больше S лучшего из наборов тракта (снимок, рельеф, снимок + рельеф)
в семействе «весь лист». Это описательное «больше», без порога различия.
Если меньше или равно — по решению Артура переходим к варианту А (отдельное
объявление).

## Обязательные проверки до вывода
- `openlin-artifact-hunter`: новый тип линий — швы съёмки, плитки GLO-30,
  береговые линии озёр, техногенные прямые, азимутальная цензура (12 направлений
  ядра → возможные «зубцы» по 15°).
- Глазом: парные окна (снимок / линии Анфисы + GTK) и контрольные окна.
- `openlin-auditor` после прогона.

## Что не меняется после прогона
Модель, порог D > 0, ядра, NMS, правила сшивки и длины, мера. Подбор любого из
этих чисел на Утсйоки — уже LINB2 со своим объявлением (это разрешено ролью
листа, но записывается как новый вариант).

## Поправка 1 (11.11.2026, по проверке `openlin-registrar`, до прогона)
1. **На сетке 100 м** разрыв 900 м = 9 ячеек, сдвиг 127 м ≈ 1,3 ячейки
   (неотличим от 100–200 м), длина 200 м = 2 ячейки; направление θ кратно 15°.
   Направление КОНЦА линии при сшивке — по ломаной (вектор от 3-й ячейки к
   концу), не по θ.
2. **Порог D > 0.** Логит 0 — граница модели при равных априорных (pos_weight
   = фон/эталон ≈ 3 в выборке обучения). На D (максимум по направлениям средних
   логитов) это свойство не переносится: D смещён вверх, в широких днищах
   долин D > 0 по всем направлениям. Число 0 не подбирается и остаётся; до
   расчёта S печатаются замеры: доля ячеек D > 0, длина скелета, длина
   наибольшей 8-связной компоненты растра.
3. **Нормировка** — то же преобразование, что в `site_table` (квантили по
   ячейкам всех окон `all_windows`), применённое ко всему листу. Так логит
   совпадает с замороженной моделью.
4. **`openlin_ref_match`**: мера (функции `rank_lines`, `evaluate`,
   `curve_score`, `recall_dir`, `long_lines`, нуль, сдвиги) не меняется;
   `main()` не используется — наборы собираются в `openlin_anfisa_lines.py`.
   K по самому короткому набору: набор Анфисы урезается по рангу длины.
   Линия в мере = 8-связная компонента растра (как у тракта): пересекающиеся
   линии Анфисы сливаются в одну. Если наибольшая компонента длиннее K·10 км,
   она в кривую не входит — это свойство меры, записывается, не исправляется.
5. **Сложение**: base = снимок ∪ add_new(рельеф, снимок); затем линии Анфисы
   добавляются ПО ОДНОЙ (каждая ломаная своей меткой, правило `add_new`:
   < 30 % ячеек в 60 м от base), а не по компонентам.
6. Растр линий обрезается по полным ячейкам снимка (`shade` конечен).
7. **Пустой набор** — S не считается, пишется «пусто», переход к варианту А по
   решению Артура. **Очень длинный набор** — потолка нет; км, доля листа и
   доля D > 0 печатаются до S, решений по ним нет; любое изменение — LINB2.
8. **Оговорка к критерию.** Анфиса обучена на метках GTK (с других листов),
   тракт — нет. Больший S против GTK не равен «лучше находит линии» (цель
   ветки — линии, GTK — сверка). Переход к варианту А решает Артур.
9. Гистограмма азимутов шагов ломаных (12 бинов по 15°) — для
   `openlin-artifact-hunter` (зубцы по 15°). При равенстве D соседей ячейка
   остаётся (≥), лишнее снимает скелет.
