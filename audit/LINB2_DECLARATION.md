# LINB2 — линии Анфисы с отбором по средней вероятности: объявление до прогона

Записано 11.11.2026, после LINB1 (`audit/LINB1_RESULTS.md`) и разбора его линий
(`outputs/fam/_linb_diag.log`), до расчёта LINB2. Решение Артура: «давай
попробуем починить» вариант Б.

## Роль и счётчик
Утсйоки — НАСТРОЙКА, описательно, `LINB2_N_TESTS` = 0, без слов «значимо».
Разбор LINB1 смотрел эталон Утсйоки — это настройка, допустимо ролью листа.
Поэтому любой итог LINB2 на Утсйоки оптимистичен и требует проверки на
нетронутом листе отдельным объявлением, прежде чем идти на Анабар.

## Что показал разбор LINB1 (настройка)
Линии Анфисы по средней карте P вдоль линии, пять равных групп: доля ячеек
у эталона (300 м, 20°) — 0,019 / 0,016 / 0,023 / 0,032 / **0,172** при нуле
≈ 0,027. Верхняя группа (2413 км) — 6,1× нуля, как тракт (рельеф 5,3×,
снимок 6,1×); нижние 80 % — на уровне нуля. По длине и прямизне различие
слабее (длинные 0,103, прямизна — без связи).

## Что меняется (одно изменение)
Линии LINB1 (те же: карта, D > 0, NMS, скелет, сшивка, отброс < 200 м — всё
без изменений) упорядочиваются по **среднему P вдоль линии** (P — среднее
логитов трёх зёрен FAM3 в ячейках ломаной, мостики сшивки входят своими
ячейками) по убыванию. Берутся первые линии, пока суммарная длина ≤
**длины набора рельефа RELU1 на этом листе (2858 км)**.

Почему этот бюджет: сравнение наборов ветки — при равной длине (правило
`openlin_ref_match`: сырая полнота растёт с густотой). RELU1 — лучший набор
тракта по S в LINB1; его длина известна без эталона. Порог по P отдельно не
задаётся и по эталону не подбирается: он получается из бюджета длины. Граница
групп разбора (0,35) в правило не входит.

Описательно (не меняет вывод) — второй бюджет: длина набора снимка UTS1
(1039 км).

## Мера и критерий
`openlin_ref_match` (функции без изменений), семейство «весь лист», наборы как
в LINB1 + «Анфиса, бюджет RELU1» (+ «Анфиса, бюджет UTS1» для сведения);
K по самому короткому. Сложение «Анфиса + снимок + рельеф» — по линиям
(`add_lines`). **«Получилось»:** S «Анфиса, бюджет RELU1» > S рельефа RELU1.
Иначе — вариант А (решение Артура). Печатается также доля ячеек у эталона
(как в разборе) против нуля 5 сдвигов.

## Обязательно
`openlin-artifact-hunter` — если «получилось» (новый набор линий пойдёт
дальше); глазом парные окна; `openlin-auditor` после прогона.

## Что не меняется после прогона
Ранжирование по среднему P, бюджет = длина RELU1, всё из LINB1.

## Поправка 1 (11.11.2026, по проверке `openlin-registrar`, до прогона)
1. **Подгонка — прямо.** Признак ранжирования (среднее P) и бюджет выбраны
   ПОСЛЕ разбора эталона Утсйоки; среднее D дало бы то же (0,186 против
   0,172), выбор P не независим. Бюджет 2858 км больше верхней группы разбора
   (2413 км) на 445 км и заходит в группу на уровне нуля — следствие бюджета.
   Критерий проверяет правило на тех же данных, по которым оно выбрано: вес
   вывода — «согласуется с разбором» (правило не сломано), а не «метод лучше».
   Слово «получилось» заменяется на «согласуется с разбором». Вес даёт только
   нетронутый лист отдельным объявлением.
2. **Перенос.** Бюджет — правило «длина набора рельефного тракта (правило
   RELU1) на том же листе, без эталона». На новом листе / Анабаре сначала нужен
   прогон рельефного тракта. Запасного правила нет.
3. **Второе семейство (описательно)** «Анфиса бюджета RELU1 против RELU1» без
   снимка: K по самому короткому из {рельеф, снимок + рельеф, Анфиса бюджета
   RELU1, Анфиса + снимок + рельеф} (≈ 285). Основной критерий — по-прежнему
   семейство с K = 103; расхождение печатается как есть.
4. **Порядок:** по убыванию среднего P, затем по убыванию длины, затем по
   номеру линии. Усечение: первые линии, пока сумма ≤ бюджета; остановка на
   первой не влезающей, без добора короткими.
5. **Мостики:** основной вариант — среднее P с ячейками мостиков; описательный
   контроль — только ячейки ветвей (без мостиков), тот же бюджет.
6. **Оговорки:** после отбора набор реже, компонент-слияний меньше — S может
   измениться не за счёт качества. Нуль разбора по 5 сдвигам груб (0,022–0,029):
   различия долей меньше нескольких долей нуля не читаются.
