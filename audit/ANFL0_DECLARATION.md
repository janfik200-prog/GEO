# ANFL0 — Анфиса выбирает линии из кандидатов CAND3; временный учитель GTK, вся цепочка под разметку

Записано 19.11.2026, до кода. Решение Артура: «до получения разметки мне придётся показывать промежуточный
результат… отполировать Анфису так, чтобы мы скормили ей разметку геологов и всё работало». Лидар не
используется. `ANFL0_N_TESTS` = 0 (p-проверок нет; всё описательно).

## Смысл
Цепочка ANFL целиком: кандидаты CAND3 → признаки линии → метка из файла линий → обучение Анфисы (FAM) →
оценка на отложенном листе → выбор линий → карта, окна, векторный файл, правила Анфисы. **Учитель сейчас —
GTK 292** (временный: только крупные линии). Когда придёт разметка, меняется только источник меток
(`labels_from_lines` с файлом линий и границей участка) — код тот же. Промежуточная карта честно
подписывается «Анфиса, учитель GTK (временно)».

## Листы и роли (как FAM3 — новых утечек нет)
Обучение — `fam_r1`, `fam_r2`, `fam_r3` (`openlin_fam.FAM3_TRAIN`, эталон `north_lin500k_292`); проверка —
Утсйоки (у FAM3 она тоже проверка); Анабар — только карта и описание; Лапландия не трогается.

## Кандидаты
CAND3 как принят (`openlin_cand3.build` + `dedupe`, без изменений) на каждом листе. На `fam_r*` CAND3 строится
впервые тем же кодом — это применение, не настройка (печать км и линий по каналам).

## Признаки линии (20; все считаются на любом листе из зимнего S2, GLO-30, ALOS AW3D30)
1–5 канал (±1); 6 сила (среднее z своего канала); 7 log длины; 8 прямизна = хорда / длина ломаной; 9–17 средние
по ячейкам линии девяти признаков FAM (`feat_<лист>.npz`, сетка 100 м, квантильная нормировка по листу как в
FAM); 18–19 среднее z ложбины и гребня по ALOS (`dem_alos30_<лист>`; та же `local_norm_nz`) — видна ли черта во
второй, независимой модели рельефа; 20 среднее расстояние ячеек линии до ближайшей линии другого канала (м) —
вместо порога 250 м (охотник: пары 127–250 м). Карта P FAM3 в признаки **не** идёт (на `fam_r*` она обучена на
GTK — утечка). Признаки 6–8, 18–20 нормируются квантилями по листу (как FAM).

## Метка (одна функция для GTK и для разметки)
`labels_from_lines(lines, area, cand, t)`: кандидаты внутри участка; «да», если ≥ 50 % ячеек линии в t от линий
учителя, иначе «нет» (одно правило 50 % — как LINB6/CAND3; полосы «не учится» нет — без нового числа). Для GTK
t = TOL_M = 300 м (допуск сверки ветки). Для разметки t — по рамке ANFL1 (127 м или замер двойной разметки).

## Обучение и выбор
`openlin_fam.fit_fam` (3 терма, LR, EPOCHS, SEEDS = 1, 2, 3 — как FAM), среднее логитов трёх зёрен. Порог выбора
— тот, что даёт наибольший F1 по длине на **обучающих** листах (сводно); переносится на Утсйоки и Анабар без
изменений.

## Оценка на Утсйоки (описательно, без критериев приёмки — это проверка цепочки, учитель временный)
F1 по длине при t = 300 м (P — доля км выбранных в t от GTK; R — доля км GTK в t от выбранных). Сравнение при
**равной длине** с выбором Анфисы: случайные кандидаты (20 повторов, зерно 1900), лучший одиночный признак
(выбран на обучении), все кандидаты (своя длина), LINB6 (при длине LINB6). Печать: правила Анфисы (центры термов
и веса по признакам), доля «да» по листам, км выбранного.

## Выход
`outputs/fam/anfl0_<лист>.npz` (метки линий, оценка), `outputs/fam/anfl0_<лист>.gpkg` (векторы выбранных линий
с каналом, оценкой, длиной — для QGIS), окна 3×3 (снимок / снимок + выбранные красным и отброшенные серым /
рельеф + то же), `outputs/fam/anfl0_<лист>/`. Охотник — на карте Анабара. Аудитор — после.

## Агенты
`openlin-registrar` → код → `openlin-keeper` → прогон → `openlin-artifact-hunter` → `openlin-auditor` → отчёт.

## Поправка 1 (registrar), 19.11.2026, до кода
Входы проверены: `feat_<лист>.npz`, `dem_alos30_<лист>` и зимние композиты есть для fam_r1–r3, utsjoki, anabar.
`git fetch`: новых коммитов в origin/lineaments нет.

1. **Роли и утечки.** Обучение fam_r1–r3 с GTK, признаки без карты P — новых утечек нет. Но Утсйоки
   НЕ слепа: выбор FAM3/FAM2 и 16 окон делались на ней с GTK (CAND1, поправка 1 п. 4). Утсйоки — проверка
   цепочки, не доказательство. Признаки 9–17 (FAM) на Утсйоки считаются без GTK — ок. Нормировка квантилями
   «по листу» на Анабаре идёт по его же признакам, без меток — ок; печатать квантили, чтобы видеть сдвиг.
2. **Порог выбора — исправить.** «Наибольший F1 на обучающих листах» по оценкам модели, обученной на тех же
   листах, оптимистичен (оценки in-sample) и перенесётся завышенным. Считать порог по схеме «лист за листом»:
   обучить на двух из fam_r1–r3, оценить на третьем, склеить три отложенных набора, взять порог по F1 по
   длине; итоговую модель учить на всех трёх, порог брать этот. Нового числа это не вводит. Порог — по
   логитам; печатать км и долю «да» на каждом листе: база «да» зависит от густоты GTK листа, поэтому на
   Анабаре, где GTK нет, км выбранного — описание, не качество.
3. **Источники чисел.** 50 % — как LINB6/CAND3 (правило ветки). 300 м = `TOL_M` (`openlin_fam.TOL_M`,
   `openlin_transfer_check`) — импортировать, не переписывать (в ветке есть 250 м в других модулях — не
   брать). 3 терма, LR 5e-3, EPOCHS 100, SEEDS 1–3 — из `openlin_fam` (импорт). **20 повторов, зерно 1900 —
   замера нет:** допустимо только как описание; печатать среднее и min–max, НЕ квантиль, не p, не слово
   «лучше/значимо». Если нужен вывод «лучше случайного» — отдельное объявление с n ≥ 2/α − 1. Зерно 1900
   выбрать как зерно, не как число из замера — оговорить.
4. **Тавтологии.** (а) Учитель GTK = мера GTK при том же t = 300 м: на обучении F1 — подгонка, цифру
   показывать только по отложенному листу (Утсйоки и схема «лист за листом»). (б) GTK — только крупные
   линии: настоящие мелкие линии получают «нет»; модель выучит «длинная и прямая» (признаки 7, 8) — это
   предвзятость учителя, а не понимание линии. Лучший одиночный признак (скорее всего длина) обязателен в
   сравнении. (в) F1 при равной длине — обязательно; без неё густой пул побеждает сам. P и R считаются на
   растре ячеек с одним t; не смешивать с «60 м» подтверждения.
5. **Что нельзя переносить из ANFL0 как результат.** Любую цифру F1/P/R против GTK; «что выбрала Анфиса»
   (правила, веса — это портрет GTK, не геологов); выбранный порог; отбор признаков; карту Анабара как
   «линеаменты по версии Анфисы» (подпись «учитель GTK, временно» — на каждой картинке и в файле gpkg).
   Переносится только код и проверка, что цепочка работает от начала до конца.
6. **Что отличается между ANFL0 и ANFL1 — зафиксировать сейчас.** В ANFL0 метка одна (≥ 50 %), в ANFL1 по
   CAND1 п. 6(iii) есть ещё «нет» < 10 % и полоса «не учится». Значит смена учителя меняет не только файл.
   Решение: в `labels_from_lines` параметр `lo` (по умолчанию `None` = полосы нет, ANFL0); ANFL1 задаёт `lo`
   своей поправкой с источником 10 % (замер, не готовое число). Остальное (признаки, модель, порог по схеме

7. **Заморозить в логе и файле до прогона.** sha256 файлов `openlin_cand1/2/3.py`, `openlin_fam.py`,
